## 前提材料

完整阅读 `docs/product/PRD.md` 的 FR-17、`UI_DESIGN_SPEC.md` 的第11章、`TECH_ARCHITECTURE.md` 的第17章、`reference/002_sticky_mode.sql`、`AGENTS.md`；`UI_PROTOTYPE.html` 与 `UI_STICKY_WINDOW.html` 仅作历史视觉参考，尺寸和交互以当前 PRD/UI 规范为准。

## 本轮实施目标：第三个 macOS 原生便签窗口 `sticky`

1. 在新的 `feat/sticky-five-pins` 分支进行（若分支名冲突使用清晰新名称），先检查 `git status`，未经授权不 push、不 merge。
2. 在 Tauri 2 新增默认隐藏的独立窗体 sticky，采用浅黄色轻量 macOS 视觉。默认舒适模式为精确 420×695 逻辑像素，精简模式为精确 340×270；只允许两档一键双向切换并持久化选择，不允许任意缩放。主窗口隐藏/关闭后，便签仍能使用；关闭便签等于 hide，不等于退出 App。
3. SQLite 采用版本化 migration，新增 `pin_order`，不清库、不重建丢失数据。后端负责最多 5 条置顶、排序与取消置顶，使用事务和参数化 SQL；保留旧版数据。
4. 标题栏只有密度直接切换、通用「切换到完整模式」、收起三个操作；密度按钮文案/图标描述目标状态。底部只有「排序」与「始终置顶」，不实现通用底部管理按钮、齿轮或独立便签设置对话框。
5. 主窗口增加「📌 便签模式」入口。置顶满五条时明确提示并保留未保存的编辑内容；既有 `StickyManagerDialog` 可调整顺序和移除。点击便签底部「排序」须进入主窗口并直接打开该对话框；若主窗口已有模态工作则安全排队，不得丢弃当前操作。复制次数不改变 `pin_order`。
6. 两档都保持五个槽位：舒适模式可展示说明/正文摘要与模板/复制动作语境，精简模式以标题为主。点击行复制完整正文到系统剪贴板，成功反馈、失败不计数；变量模板必须先填变量，复用现有 QuickWindow 变量功能。便签不要自行重复开发另一套复制流程。
7. 支持标题栏拖动、可切换 always-on-top，并将密度、可见性、位置、置顶状态保存到本地 app_settings；显示器拔插后保证窗口在可见桌面工作区。
8. 仅授予必要 Tauri window/clipboard 权限，不新增云、账号、联网、模型调用、自动粘贴、辅助功能权限。
