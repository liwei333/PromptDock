# AGENTS.md — PromptDock 本地桌面 App 协作准则

> 将本文件复制到 **PromptDock 工程仓库根目录**。适用于 Codex/其他 AI 编程代理在此仓库中的全部工作。

## 1. 任务与范围

本项目是一款个人自用、macOS 本地离线提示词管理工具，使用 Tauri 2 + Vue 3 + TypeScript + Rust + SQLite。**不开发账号/联网/同步/云数据库/iOS 版本/自动粘贴/模型调用/自动更新/埋点**，除非用户后续明确更改 PRD。

需求真值优先级：
1. `docs/product/PRD.md`（产品范围和验收）
2. `docs/product/UI_DESIGN_SPEC.md`（视觉/交互）
3. `docs/product/TECH_ARCHITECTURE.md`（架构和安全约束）
4. `docs/product/UI_PROTOTYPE.html`（仅提供配色、CSS Token 和轻量 macOS 视觉语言参考；不作为布局、导航、按钮位置或交互真值）

如文档之间冲突：停止相关冲突实现，先在反馈中列出冲突和建议，再按最高优先级规范执行；不自行添加云功能来解决。

## 2. Git 工作纪律

- 每个独立开发阶段使用新的 `feat/...` 或 `fix/...` 分支；**禁止直接在 main 开发**。
- 启动任务先执行 `pwd; git status --short --branch; git branch --show-current; git log -1 --oneline` 并记录结果。
- 发现已有用户未提交修改时，不覆盖、不 stash、不 reset；调整实施范围并汇报。
- 按阶段完成最小可审查 commit，可保留未 push 状态；**不自动 push、merge、rebase 到 main**，除非用户明确授权。
- 不修改无关仓库，不下载或复制其他产品业务代码，不接触生产系统。

## 3. 开发约束

- 真实数据一律落到 `app_data_dir/promptdock.sqlite3`（SQLite），**不使用 localStorage** 作为业务数据库。
- 首次运行只创建六个默认分类，**不自动注入演示提示词**。
- Rust commands 为唯一数据操作 API。禁止前端直接拼动态 SQL、禁止通用任意 SQL IPC 命令。
- 同一 `SqlitePool` 提供主窗口、quick 快捷窗口和 sticky 便签窗口的数据访问；通过刷新/内部事件处理跨窗更新。
- 一键复制必须使用 Tauri clipboard-manager。成功后才增加 `copy_count`；复制成功但统计失败需区分错误级别。
- 全局快捷键为 `Option + Space`，仅在 Rust 进程中注册一次。macOS 焦点唤起在原生 App 验证。
- `sticky` 第三窗口按 `PRD.md` FR-17 显示最多 5 条，持久化 `pin_order`，不可根据复制次数重排、不可静默替换第六条、不可在前端模拟独立窗体当作交付。
- 快捷窗口只复制到剪贴板，不控制其他程序、模拟 `⌘V` 或请求不相关辅助功能权限。
- 变量模板只做**一次文本替换**，变量值视为字面文本，不执行任何模板代码。
- 所有用户内容在 UI 上只作为纯文本展示，不使用 `v-html`，不运行 HTML/JS。
- JSON 导入先全部校验并预览，再事务导入；替换必须安全备份后继续。
- 不连接任何远程 API、字体 CDN、遥测、Crash 上传、自动更新源。
- 锁定依赖，提交 `pnpm-lock.yaml` 与 `Cargo.lock`；对代码改动执行相应测试。

## 4. 阶段推进约定

- 严格按 `docs/product/CODEX_TASKS.md` 的阶段 0~3、3B、4 迭代；除用户直接要求外，不跨多个阶段一次性提交。
- 先实现并测试**真实 SQLite CRUD + 系统剪贴板**，再进行快捷窗和美术微调。
- 单项功能完成的标准是：代码路径真实 + 能运行 + 有测试或手工复现证据，不是「页面看得到按钮」。
- 若平台或权限行为无法在当前非 Mac 环境验证，必须明示 `UNVERIFIED_MACOS_RUNTIME`，不能写成已通过。
- 若缺失必须的开发依赖，说明实际缺失内容和安装指令；不要假设依赖已存在。

## 5. 修改边界

- 界面沿用历史 HTML 原型的配色、CSS Token 与轻量 macOS 视觉语言；当前主窗口布局、导航、按钮位置和交互以 `PRD.md`、`UI_DESIGN_SPEC.md` 第 3–4 节及当前组件合同为准。**V1.1 例外**：独立 `sticky` 便签允许浅黄色主题；默认舒适模式为 420×695、精简模式为 340×270，只有这两个精确受控尺寸，不允许任意缩放。当前便签行为以 `PRD.md` FR-17 为准，历史原型不构成固定单一尺寸要求。
- 如改数据表，必须新增顺序 migration 并提供升级兼容性测试；不可删现有用户库。
- 新增依赖需解释解决的问题；避免引入不必要的 Node 服务端、ORM、WebSocket、AI SDK。
- 故障时优先保护数据库：禁止在“打不开库”时删除老库新建空库。

## 6. 每阶段验收反馈模板

```text
【阶段】
【Git 分支 / 最新提交 / 工作区状态】
【本阶段实现】
【实际变更文件】
【执行命令和结果】（真实命令、exit code、日志摘要）
【验收用例】（通过/失败/未验证；证据）
【实际数据路径】
【原生 macOS 测试】（是否在 Mac 上测试，没测必须明确）
【遗留缺陷】（P0/P1/P2）
【是否达到进入下一阶段的门槛】
```

禁止「应该能」「理论上通过」「我已经完成」而没有运行验证；不伪造构建和测试输出。
