# PromptDock — macOS 桌面端 UI/UX 设计规范 V1.1

> 配套原型：`UI_PROTOTYPE.html`（已获得认可的主页面）和 `UI_QUICK_WINDOW.html`（新增独立快捷窗口示意）；截图：`reference/UI_PREVIEW.png`。
>
> 本文不重设计视觉风格。以原型结构、字体、间距、色彩和卡片交互为依据，指导 Vue 3 组件化与 macOS 原生快捷浮窗落地。

## 1. 设计理念

**个人工具 / 专注 / 复制优先 / 低干扰。** 用户应在 1 次点击或一次搜索后直接得到剪贴板内容。信息层级按：复制行动 > 标题 > 分类/标签 > 摘要 > 使用统计。收藏和置顶负责效率，不做多余的团队或云端入口。

| 原则 | 实现 |
|---|---|
| 视觉延续 | 复用原型深海军蓝侧栏、蓝紫强调色、浅灰工作区、白色圆角卡片 |
| 行为真实 | 复制按钮调用系统剪贴板；持久化调用 Rust/SQLite；不能仅显示成功消息 |
| 搜索优先 | 主界面搜索大且明显，浮窗一出现即聚焦搜索 |
| 简单可读 | 不做品牌营销 Banner、AI 自动生成介绍、排行榜或云同步指示 |
| 错误清晰 | 写入/导入/复制失败，必须用失败提示而非成功 Toast |

边角样式：主内容卡片 `border-radius: 15px`，面板 `16px`，按钮约 `9px`，快捷浮窗约 `15px`。卡片阴影应轻，不做霓虹光效/玻璃拟态大面积覆盖。

### 2.2 字体与密度

- 字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`，不加载在线 Google Fonts。
- 主标题 `26px / 780`；区块标题 `15px / 750`；卡片标题 `13–15px / 700`；说明文本 `11–13px`；辅助计数 `10–11px`。
- 正文编辑器保留换行，可使用 macOS 系统等宽字体（例如 `SFMono-Regular` 的系统候选）；确保长行横向滚动或柔性换行，不覆盖输入。
- 触控鼠标可点击区域建议 ≥ 32px；键盘可见焦点框使用蓝紫半透明描边。

```text
┌──── 253px 固定左侧栏 ────┬───────────────────────────────────────────────┐
│ PromptDock 品牌          │ 顶部条 76px：面包屑     导入 导出 [+新建]   │
│ 我的工作空间             ├───────────────────────────────────────────────┤
│ ─ 工作台 ─              │ 标题：我的提示词库                             │
│ 全部提示词        数量   │ 搜索框   [全部/已收藏/变量模板] [排序]        │
│ 最近使用          数量   │                                               │
│ 我的收藏          数量   │ ┌ 快捷复制 ─────────────────────────────────┐ │
│ 快捷置顶          数量   │ │ 置顶 1    置顶 2    置顶 3                │ │
│ ─ 分类管理 + ─          │ └───────────────────────────────────────────┘ │
│ 技术研发  / 投资研究     │ 提示词列表  (三列/二列响应式卡片)             │
│ 产品规划  / 内容创作     │ ┌ 卡片 ┐   ┌ 卡片 ┐   ┌ 卡片 ┐              │
│ 商业运营  / 通用效率     │ │复制  │   │复制  │   │复制  │              │
│                         │ └──────┘   └──────┘   └──────┘              │
│ 快捷取用 ⌘K            │                                               │
│ 本机数据  导出备份       │                                               │
└─────────────────────────┴───────────────────────────────────────────────┘
```

- **主窗口建议初始尺寸**：`1360 × 860`；最小尺寸 `1024 × 700`。
- 左侧栏：`253px`，主窗缩小时至 `227px`（参照原型）。顶部条 `76px`；主内容最大宽度约 `1540px`，水平内边距 `27–37px`。
- 主卡片网格：宽视图 3 列，窗口变窄改 2 列。仅为 PC 使用，最小窗口下维持 2 列，如出现可读性问题可退化为 1 列。
- 置顶快捷区：最多 3 个快捷项，先置顶优先，再使用次数；不足 3 不插占位卡。
- 主内容垂直滚动，导航栏独立滚动。保持鼠标滚轮正常。

> **重要文案改动**：正式 Tauri 客户端应把原型的「仅存储在当前浏览器 / 浏览器本地保存」替换为「仅保存在这台 Mac / SQLite 本地保存」，状态栏不要使用暗示联网成功的“绿色在线点”。但 `UI_PROTOTYPE.html` 作为浏览器演示依旧需要如实写「浏览器本地保存」，避免误导。

## 5. 核心交互状态机

### 5.1 普通提示词点击复制

```text
卡片 Copy 点击
   └─[读取完整正文]→[系统剪贴板 writeText]
                         ├─ 成功 → Toast 已复制 → 更新使用次数与最近使用时间
                         │          └─ 次数写入失败 → 保留复制成功，但展示统计失败
                         └─ 失败 → 错误 Toast → 绝不增长次数
```

- 点击按钮目标须拦截事件冒泡，**不打开详情抽屉**。
- 按钮在异步复制期间变 loading，避免用户无反馈；处理完恢复正常。
- Toast 约 2.5 秒自动消失；错误应允许再次复制。
- 有变量的卡片按钮显示「填写并复制」；进入变量面板，不直接写剪贴板。

### 5.2 变量模板

```text
选择模板 → 详情抽屉打开 → 变量表单自动生成
                     → 用户填写 → 实时结果预览
                     → 全部非空？ ─ 否 → 聚焦首个未填项、显示错误
                                  └ 是 → 复制替换后的全文
```

- `{{变量名}}` 同名去重；原文预览使用**纯文本**，不可 `v-html` 注入。
- 输入框顺序与正文中变量首次出现的顺序相同。
- 切换到另一条提示词时销毁当前变量输入，不泄露到下一条。
- 点击正文时只浏览，不自动替换任何文本。

### 5.3 进入编辑器

- 点击「新建」弹居中表单（约 `670px`）；自动聚焦标题。
- 新建默认分类「通用效率」，首次空库仍可创建。
- 编辑则回填全部字段并保留原始正文的所有换行和缩进；提交完成刷新列表和抽屉。
- 表单 `保存` 禁止空标题/空正文，超过长度时报错，不静默切片。
- 有未保存内容时按关闭/外部遮罩/Esc，弹「放弃修改？」；选择继续编辑后保留原输入。
- 删除入口在编辑弹窗底部左侧，需二次确认，不采用悬浮式小叉号误触删除。

## 6. 快捷浮窗详细 UX（正式 App 的补充页面）

**视觉沿用原型中的快捷面板**：白色 680px 搜索弹窗、灰紫遮罩、候选左侧图标、右侧「复制/填变量」提示。真正独立浮窗不用覆盖整屏遮罩，仅显示面板自身。

| 属性 | 设计基线 |
|---|---|
| Tauri Window label | `quick` |
| 初始状态 | hidden；默认无任务栏独立图标（具体视 macOS 支持） |
| 默认热键 | `Option + Space` |
| 尺寸 | 约 `680×520`，最小根据屏幕高度自适应 |
| 位置 | 当前屏幕上半部分居中（取活动屏幕，无法获取时主屏居中） |
| 输入框 | 自动聚焦；placeholder「搜索并快速复制提示词...」 |
| 推荐结果 | 置顶优先 + 高频优先，最多 12 条，可键盘上下选中 |
| Enter | 普通词复制当前选中项；模板打开变量表单 |
| Esc | 关闭快捷窗；若变量表单打开则先关闭表单 |
| 复制成功 | Toast 简短反馈并自动隐藏浮窗 |
| 复制失败 | 浮窗保持，错误反馈，不丢输入 |
| 快捷键被占用 | 提示冲突，可从主窗口按钮进入应用内面板 |

快捷面板不自动代替用户执行 `⌘V`；不要因“更顺畅”擅自引入剪贴板历史监听、辅助功能权限或模拟目标应用输入。

## 7. 搜索与筛选 UI 规则

- 搜索框默认空，输入时仅筛当前视图集合，150ms 防抖；分类与筛选标签叠加，排序规则单独选择。
- 按分类导航时，清空搜索词和快捷筛选标签；复用同一个搜索框。
- 主列表空数据的 CTA：「新建提示词」；搜索无结果的 CTA：「清除搜索」。
- 页面顶部的数量和侧栏计数应从真实数据库查询结果或 store 正确计算；不得固定显示演示数据。
- `⌘F`（可选但建议 P0）主窗内聚焦列表搜索；不能劫持用户正在输入正文编辑器时的正常行为。

## 8. 响应、可访问性和反馈

- `:focus-visible` 蓝紫色外圈 3px 左右；图标按钮有可读 `aria-label`。
- 动画尽量短：抽屉约 200ms、浮窗约 150ms；尊重 `prefers-reduced-motion`。
- 长文本卡片只显示**摘要裁切**，详情和复制保留**完整正文**。
- 变量表单输入、删除确认、导入确认、快捷浮窗应能使用键盘完成。
- Toast：保存/复制成功用成功样式；复制或存储失败用错误样式。不使用「绿色在线」表达本地存储成功。
- 正式 `QuickPalette` 需要真实的候选高亮状态和 ↑↓ 操作；现有原型只演示基础结果列表，不能据此免除键盘导航开发。

## 9. 视觉和功能一致性验收

- [ ] 主窗口布局、导航、按钮位置、整体颜色与 `UI_PROTOTYPE.html` 基本一致。
- [ ] 正式版用「本机 SQLite」文案，不再写「当前浏览器保存」。
- [ ] 主卡片点击与复制按钮事件严格分离。
- [ ] 变量提示词必须走输入/预览/复制，而不是复制 `{{...}}`。
- [ ] 空库、搜索空态、加载中、复制成功、复制失败、导入冲突均有清晰可读 UI。
- [ ] 主窗口 `⌘K` 与系统快捷浮窗两个入口均真实可用。
- [ ] 1024×700 下不横向溢出核心功能、无重要按钮被遮挡。

## 10. 给实现者的注意事项

原型是一份**交互效果参考**，不是最终框架源代码：它使用浏览器 `localStorage`、`document.execCommand('copy')` 兜底、内置演示数据和单文件事件委托。正式版必须拆分 Vue 组件，并从 Rust SQLite Repository 获取真实状态。不要靠 iframe 嵌入原型、复制它的 `localStorage` 读写、或用 UI 假数据替代后端。


## 11. V1.1 新增第三窗口：五条置顶便签（P0）

**像 Mac 桌面便签，但复制的是存储在 SQLite 的完整提示词。** 参考 `UI_STICKY_WINDOW.html`（独立便签原型）、`UI_PROTOTYPE.html` 顶部的「📌 便签模式」入口，以及 `reference/STICKY_WINDOW_PREVIEW.png`。

| 元素 | 设计标准 |
|---|---|
| `sticky` 独立窗口 | **340 × 270** 逻辑点，P0 固定；首次启动隐藏 |
| 背景 | 淡黄 `#FFF3AC`，顶部轻渐变；边框 `#DFC96D`，圆角 9px |
| 标题栏 | 46px 高，可拖动区域；包含「快捷便签」「n/5」、置顶按钮、管理按钮、关闭按钮 |
| 提示词行 | 5 行，每行 36px、间距 4px；两侧各约 9px 内边距 |
| 文本 | 11.5–12px 中文优先系统字体；单行省略；全文只在剪贴板中，不在小窗预览 |
| 排序标记 | `01`～`05` 固定序号；左右按钮不应因文案长度改变位置 |
| 操作反馈 | 成功 1–1.8 秒明显绿色/勾选状态，失败显示错误，不假装复制成功 |
| 空位 | 虚线细框，「空位 X · 在主库中选择置顶」 |
| 底部 | 高约 30px，「整行点击 · 复制全文」「管理置顶」 |
| 默认层级 | 始终置顶开；可关闭并持续记住。HTML 模拟不能证明系统级置顶 |

**页面交互**：
1. 主窗口右上角「📌 便签模式」打开；系统 Dock 菜单/应用菜单也能唤起。
2. 点击非模板行的任意位置复制，并保持窗口可见。标题不展示全文，复制必须得到 `prompt.body` 原文。
3. 点击模板行会启动变量填写（由已实现的 `quick` 窗口完成），不许把带花括号的原文直接复制。
4. 管理窗口可上移、下移、移除；新增第六条应明确拒绝或要求确认替换。
5. 仅可拖拽标题栏的非按钮区域，按钮点按不触发拖窗；窗口边界落在可见工作区。
6. 如果已有五条再置顶，编辑器显示错误并保持打开，不清除尚未保存的输入。
7. 便签是独立 Webview；主窗口关闭后仍能运行，必须有明确「退出软件」途径。

**容易做错的四点**：
- 不要把原来的 `quick`（680×520、搜索 12 条）缩小代替 `sticky`（340×270、固定五条），它们功能不同。
- 不要用 `style='position:fixed'` 代替系统置顶；CSS 仅是单 HTML 演示。
- 不要因为复制次数变化而重新排序五行；位置来自数据库 `pin_order`。
- 不要在正式 Tauri 中用 `localStorage` 存放提示词、排序或窗体位置；窗体位置可用已有 `app_settings` 持久化。
