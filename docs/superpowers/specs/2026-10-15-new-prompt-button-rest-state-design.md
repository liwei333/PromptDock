# “新建提示词”主按钮视觉一致性设计

## 背景

主窗口提示词列表标题栏中的“新建提示词”和详情区域中的“一键复制”都使用 `PdButton` 的 `primary` 变体，但标题栏的通配后代 `span` 样式覆盖了按钮内部文字和图标的继承颜色，导致“新建提示词”显示为蓝底灰字。用户要求它直接参考“一键复制”，保持主操作按钮风格统一。

## 目标

- 让标题栏“新建提示词”与“一键复制”使用同一套 `primary` 视觉。
- 默认状态为蓝色背景、纯白文字和图标。
- 鼠标悬停、按压和键盘焦点状态继续由公共 `PdButton` 提供。
- 保留清晰的键盘焦点和按压反馈。
- 不新增依赖，不改数据流、事件和可访问名称。

## 方案比较

1. **修正标题栏选择器（采用）**：把 `.prompt-list-pane > header span` 收窄到真正需要着色的排序提示，移除它对按钮内部 `span` 的误伤。这样两个按钮自然共享 `primary` 样式，并修复根因。
2. 给“新建提示词”内部文字加白色覆盖：能修复当前截图，但会把错误的宽泛选择器继续保留，后续新增按钮仍可能被误伤。
3. 为按钮新增专用 variant：视觉已经由 `primary` 精确表达，新增公共 API 会制造重复样式和不必要复杂度。

## 视觉与交互

- Rest：复用 `--pd-accent` 蓝色背景，文字和加号均为白色。
- Hover：复用 `--pd-accent-hover` 深蓝背景，文字和加号保持白色。
- Active：继续使用公共按钮的 1px 按压位移。
- Focus-visible：继续复用全局 `--pd-focus-ring` 蓝色焦点环。
- Disabled：沿用全局禁用状态，仅在业务真的传入 `disabled` 时出现。

按钮尺寸、文案、图标、点击事件和键盘行为不变。

## 实现边界

- 保留“新建提示词”现有的 `variant="primary"`，不添加专用变体。
- 收窄 `global.css` 中标题栏提示文字的选择器，仅让“最近使用”排序提示使用次要文字色。
- 不修改 `PdButton.vue` 的主按钮配色，不引入 Ant Design、Element UI 或新依赖。

## 验证

- 组件测试确认按钮仍发出 `new` 事件并保留 `primary` 变体，同时标题栏通用样式不会再命中按钮内部文字。
- 运行格式检查、类型检查、相关 Vitest、生产构建。
- 视觉检查默认/hover/active/focus-visible 四种状态；若不能自动稳定捕获 hover，则明确记录为手工验证。
