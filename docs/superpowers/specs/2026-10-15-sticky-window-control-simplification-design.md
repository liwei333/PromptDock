# PromptDock 便签窗口控件精简设计

**日期：** 2026-10-15  
**状态：** 用户已确认交互方向，待复审
**范围：** `sticky` 独立便签窗口及其进入主窗口管理场景的定向导航；不改变快捷搜索窗口、SQLite 数据结构或主窗口管理能力

## 1. 背景与目标

当前便签窗口同时提供三处进入完整主窗口的入口：标题栏“切换到完整模式”、底部“管理”、设置弹窗中的“打开完整窗口”。标题栏齿轮仅用于打开该弹窗，而弹窗中的密度切换又是便签日常高频操作。这造成入口重复，并让“舒适/精简”切换需要两步操作。底部“排序”目前也只执行普通切窗，没有直接打开排序管理，因此需要在保留其任务语义的同时修正真实行为。

本次优化的目标是：

- 保留一个清晰、稳定的通用入口进入完整主窗口；
- 删除重复的管理入口和只承载重复功能的设置弹窗；
- 将显示密度切换提升为标题栏的一键操作；
- 保留与具体任务直接相关的“排序”和“始终置顶”；
- 不改变现有数据持久化、窗口尺寸切换和错误处理机制。

## 2. 已确认的信息架构

### 2.1 标题栏

标题栏右侧按以下顺序保留三个图标按钮：

1. **密度切换**：取代现有齿轮设置按钮；
2. **切换到完整模式**：保留，作为进入完整主窗口的唯一通用入口；
3. **收起便签**：保留现有行为。

密度切换按钮直接执行切换，不再打开中间弹窗：

- 当前为舒适模式时，按钮的可访问名称与提示文字为“切换到精简模式”；
- 当前为精简模式时，按钮的可访问名称与提示文字为“切换到舒适模式”；
- 图标随目标模式变化，使用语义明确的收拢/展开图标；
- 点击后复用现有 `setStickySettings({ density })` 流程持久化设置并调整原生窗口尺寸。

界面文案使用用户指定的“精简模式”；内部类型继续沿用现有 `compact`，避免无意义的数据模型迁移。

### 2.2 内容区域

提示词列表、复制反馈、模板处理、空位提示和五条上限均保持不变。舒适模式继续展示描述等扩展信息，精简模式继续使用仅标题的紧凑行。

### 2.3 底部操作栏

底部操作栏调整为：

- 左侧保留“排序”，点击后进入完整窗口并直接打开“管理置顶”弹窗；
- 右侧保留“始终置顶”开关；
- 删除“管理”，避免与标题栏“切换到完整模式”重复；
- 不再显示任何设置弹窗入口。

“排序”虽然也会进入完整窗口，但它表达的是明确任务，不视为重复的通用入口。实现上扩展现有 `enter_main_mode` 调用，增加可选的强类型 intent `manage-sticky`：普通标题栏入口不传 intent，“排序”入口传入该 intent；主窗口切换成功后，只向 `main` 窗口发送打开现有 `StickyManagerDialog` 的定向事件。弹窗自身的排序、移除和刷新流程保持不变。

## 3. 删除范围

从 `StickyWindow.vue` 删除：

- 标题栏齿轮“便签设置”按钮；
- `PdDialog` 形式的“便签设置”弹窗；
- 弹窗内“窗口显示密度”和“打开完整窗口”两行；
- 底部“管理”按钮；
- 仅为该弹窗服务的状态、关闭守卫、样式和导入。

主窗口中的 `StickyManagerDialog.vue` 不在删除范围内，它仍负责五个位置的排序和移除。

## 4. 交互与状态契约

### 4.1 初始化

便签挂载后仍读取持久化的 `alwaysOnTop` 与 `density` 设置，并用独立的 `settingsReady` 表示读取已成功。在读取成功前：

- 密度切换按钮禁用，避免用未知旧值覆盖已保存设置；
- 始终置顶开关同样禁用，避免以未知本地默认值覆盖持久化设置；
- 标题栏完整模式和收起按钮不受密度读取影响。

只有当前且有效的 `getStickySettings()` 请求成功后，`settingsReady` 才变为 `true`。读取失败时保留现有错误提示，密度按钮和始终置顶开关继续处于安全禁用状态；标题栏“切换到完整模式”和“收起便签”仍可用，用户可进入主窗口或重启应用以重新初始化。本次不增加额外重试控件，以保持界面精简。

首次安装以及旧设置中缺少 `density` 字段时，默认使用现有的舒适模式 `comfortable`（420×695）。精简模式 `compact` 为 340×270。两者是离散的持久化模式，不开放任意拖拽缩放。

### 4.2 密度切换

切换过程遵守以下规则：

- 舒适 `comfortable` 与精简 `compact` 双向切换；
- 请求进行中按钮禁用并标记 `aria-busy="true"`，防止重复提交；
- 只有最新且仍有效的请求可以更新界面状态；
- 组件卸载后，迟到响应不得再修改本地状态；
- 成功时，以后端返回的 `settings.density` 为准；
- 失败时保留原显示密度，并继续显示现有可访问错误“无法调整便签尺寸”；
- 不增加成功弹窗或提示，窗口尺寸与内容密度变化本身即为即时反馈。

### 4.3 进入完整窗口

- 标题栏“切换到完整模式”调用 `enterMainMode()`，只切换到普通主窗口；
- 底部“排序”调用 `enterMainMode("manage-sticky")`，切换成功后由 Rust 向 `main` 窗口发送定向事件，主窗口收到事件后打开现有 `StickyManagerDialog`；
- 转换进行中沿用现有防重复、失败提示和卸载安全机制；
- 两个入口共享同一切窗忙碌锁，连续点击或交叉点击只允许一个请求；
- 带 intent 的命令只有在切窗与定向事件均成功时才返回成功；若主窗口已打开但事件发送失败，“排序”入口显示“已打开完整窗口，但无法打开置顶排序”，不得伪装成排序界面已打开；
- 页面上不再出现底部“管理”或弹窗“打开完整窗口”。

### 4.4 始终置顶

始终置顶开关的调用、持久化、失败回滚与忙碌状态均保持不变。

## 5. 视觉与可访问性

- 新密度按钮复用现有 `PdIconButton`，与完整模式、收起按钮保持尺寸、圆角、悬停与焦点样式一致；
- 图标为辅助表达，按钮必须通过动态 `aria-label` 和 tooltip 明确说明切换目标；
- 按钮禁用时保持可辨识，不能仅依赖颜色表达忙碌状态；
- 删除弹窗后，不残留不可见焦点节点、遮罩或 Escape/外部点击监听；
- 舒适和精简两种窗口尺寸下，标题栏三个按钮都必须完整可见，底部“排序”与“始终置顶”不得拥挤或溢出。

## 8. 验收标准

1. 标题栏不再显示设置齿轮，而显示可直接操作的密度切换按钮。
2. 舒适模式下按钮提示“切换到精简模式”，点击一次即可持久化并进入精简模式。
3. 精简模式下同一按钮提示“切换到舒适模式”，点击一次即可持久化并返回舒适模式。
4. 标题栏“切换到完整模式”保留且功能正常。
5. 页面不存在“便签设置”弹窗、底部“管理”按钮或弹窗“打开完整窗口”。
6. 底部仍有“排序”和“始终置顶”；始终置顶行为不变，“排序”修正为直接打开主窗口的置顶管理弹窗。
7. 初始化未完成时密度按钮禁用；初始化失败后密度按钮与始终置顶保持安全禁用，且不会写入未知设置。
8. 舒适和精简模式下均无控件溢出，键盘焦点、动态可访问名称、tooltip 和错误提示可用。
9. 标题栏完整模式只打开普通主窗口；底部“排序”直接打开主窗口的 `StickyManagerDialog`。
10. 相关单元测试、Rust 测试、全量前端测试与生产构建通过；原生 macOS 行为需在 `.app` 中实测并如实记录。

### 8.1 自动化测试矩阵

1. 设置读取未完成：密度按钮禁用，完整模式和收起仍可用；
2. 设置读取失败：密度按钮与始终置顶保持禁用，点击不调用 `setStickySettings`；
3. 舒适模式：名称和 tooltip 为“切换到精简模式”，一次点击写入 `compact`；
4. 精简模式：名称和 tooltip 为“切换到舒适模式”，一次点击写入 `comfortable`；
5. 密度请求期间：按钮禁用且 `aria-busy="true"`，连续点击只产生一次 IPC；
6. 密度成功：以后端返回值更新 UI 并清除 busy；密度失败：保留原模式、清除 busy、显示可访问错误；
7. 组件卸载：迟到的初始化、密度成功或失败响应不再更新状态或错误；
8. DOM 中不存在旧设置齿轮、设置 dialog、遮罩、底部“管理”和弹窗“打开完整窗口”；相关专用 CSS 选择器也已删除；
9. 标题栏完整模式调用无 intent 的普通切窗；“排序”调用 `manage-sticky` intent；二者共享防重复锁；
10. Rust 命令在普通切窗时不发管理事件，在 `manage-sticky` 时只向 `main` 发事件，并正确报告切窗或事件发送错误；
11. 主窗口只在收到目标事件时打开 `StickyManagerDialog`，卸载后不再响应；
12. 原生 `.app` 手工验证：420×695 与 340×270 下三个标题栏按钮、底栏、焦点、tooltip 和错误提示均无裁切，并验证双向切换及重启持久化。不得用 jsdom 布局断言替代该项。

## 9. 备选方案与决策

### 方案 A：直接密度切换 + 保留完整模式（采用）

减少一次点击，移除重复入口，同时保留用户明确要求的主窗口通道。信息架构最清晰，改动局部，继续复用已有状态和 API。

### 方案 B：连同完整模式按钮一起删除（不采用）

界面更极简，但会失去稳定的通用返回入口。用户已明确选择保留。

### 方案 C：保留设置弹窗，仅删除重复管理入口（不采用）

实现改动最小，但密度切换仍需两步，无法满足“一点即切换舒适/精简”的核心要求。
